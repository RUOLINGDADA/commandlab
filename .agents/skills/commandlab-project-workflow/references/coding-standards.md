# 编码与内容规范

## 结构

- 以业务功能划分文件夹，公共能力放入职责单一的 package。
- 源代码目标少于 500 行，硬上限 1000 行；生成文件和锁文件除外。
- 新实现取代旧实现时，删除确认无调用的旧代码；不要添加未被要求的兼容层、转发层或重复配置。
- 不创建空目录、假后端、占位数据库或无法验证的基础设施文件。

## 中文注释

- 导出类型、公共函数和组件使用中文 TSDoc 说明用途、输入、输出及重要约束。
- 复杂状态转换、安全边界、容易误解的算法和业务原因必须使用中文注释。
- 代码已经直接表达的赋值、循环和样式不写逐行复述式注释。

## 质量

- TypeScript 开启严格模式，禁止无理由的 `any`。
- 内容、外部输入和持久化数据必须通过共享 Schema 校验。
- 修复缺陷时先建立可复现测试，再修复并记录。
- 提交前至少执行受影响范围的格式、类型、测试和构建检查。
