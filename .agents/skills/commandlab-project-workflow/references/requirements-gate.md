# 需求确认协议

## 修改前

1. 读取项目状态、最近交接和与需求相关的代码或内容。
2. 只询问无法从仓库得知且会实质改变结果的问题。
3. 用简洁语言复述目标、包含范围、不包含范围和验收标准。
4. 等待用户明确回复确认、开始或同等含义后再修改文件。

即使需求很小，也必须先复述并获得确认。只读检查、测试和信息收集可在确认前执行。

## 修改中

- 新需求只是已确认目标的补充细节时，记录到当前任务并继续。
- 新需求改变架构、数据、安全、公开接口或交付范围时，暂停修改并重新确认。
- 不把一次授权扩展为发布、删除远程资源、创建账号或其他未明确要求的外部操作。

## 验收表达

验收标准必须描述用户可观察的结果，并包含必要的失败或边界场景。不要只写“代码完成”或“测试通过”。
