## 核心模型

区分只获取的 fetch 与会整合的 pull。

不要从背诵参数开始。先运行 git status 确认当前分支、暂存区和工作区，再判断命令会移动引用、改变暂存区，还是改写工作区。把影响区域说清楚后再执行，可以避免大多数误操作。

## 操作顺序

1. 在独立的 commandlab-git-lab 目录建立实验环境。
2. 使用 git fetch origin 完成本节核心观察或动作。
3. 运行 git remote -v 检查结果，不用“没有报错”代替验证。
4. 对照状态或提交图解释变化，然后执行安全清理。

## 进一步理解

git fetch origin 与 git pull --ff-only 的职责并不相同。在团队仓库中还要考虑命令是否改变已经共享的提交 ID。整理历史前应建立临时分支或标签，并确认恢复路径。
