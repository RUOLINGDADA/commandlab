## 本节要解决什么

把本地提交重放到新基底，并在隔离仓库中练习、验证与安全清理。先把命令要影响的对象说清楚，再执行；这样你能判断输出是否合理，而不是只看“有没有报错”。

## 先准备，再操作

1. 进入课程上方练习步骤创建的独立仓库，先运行 `git status`。
2. 对照步骤中写出的前置状态；如果当前分支、文件或远端不存在，先完成准备动作，不要跳过。
3. 执行核心命令 `git rebase main`，把完整输出和退出码保留下来。
4. 使用练习要求的验证命令检查结果，再解释哪一个对象发生了变化。
5. 确认没有需要保留的修改后，执行平台对应的定向清理命令。

## 命令拆解

`git rebase main`：把当前分支提交重新应用到新基底，会生成新的提交 ID；共享分支不要直接改写历史。

这条命令的结果可能因 Git 版本、当前分支名和仓库内容不同而变化。稳定的验证方式是查看状态、引用或差异，而不是复制某个固定哈希或时间。

## 出错时怎么办

先停止继续输入，保留原始错误；再运行 `git status`、`git log --oneline --all` 或本节列出的只读检查，确认自己所在目录、分支和前置对象。需要改写历史的命令只在练习仓库或未共享分支中执行；不确定时先创建分支或记录当前提交：`git branch backup-before-16-rebase`。

## 课后复盘

用自己的话回答：命令读取或改变了哪个对象？验证输出中哪一行证明目标达成？如果结果不对，最先检查哪个前置条件？清理时为什么只能删除本节创建的资源？
