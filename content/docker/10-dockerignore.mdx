## 核心模型

用 .dockerignore 减小上下文并避免泄露。

Docker CLI 只是客户端，真正管理镜像、容器、网络和卷的是 Docker Engine。执行命令前先说明操作对象和生命周期，执行后再用结构化检查命令确认结果，避免把“进程启动”误判为“服务可用”。

## 操作顺序

1. 在 commandlab-docker-lab 目录确认 docker version 同时显示客户端和服务端。
2. 执行 docker build -t commandlab/demo:ignore . 完成本节核心动作。
3. 运行 docker image inspect commandlab/demo:ignore 检查实际对象状态。
4. 只删除 commandlab 前缀资源，避免影响本机其他项目。

## 进一步理解

docker build -t commandlab/demo:ignore . 与 docker build --no-cache -t commandlab/demo:nocache . 面向的观察角度或对象不同。生产环境还必须考虑权限、资源上限、持久化位置、网络暴露和可重建性；任何清理动作都要先确认数据是否位于卷或外部存储。
